# Naroom Beta 1 AI Moderation·안전 처리 지침

## 1. 적용 범위

- 사용자 기록 입력
- 개별 기록 AI 회고
- 주간 AI 회고
- AI 후속 질문과 대화
- 감정·태그 후보 추출
- AI 응답 평가와 신고

## 2. 기본 정책

1. 사용자 기록은 Moderation 결과와 관계없이 먼저 저장한다.
2. Moderation은 기록 저장·계정 제재가 아니라 AI 처리 경로를 결정하는 데 사용한다.
3. 사용자의 감정, 경험, 욕설, 피해 사실, 위기 표현을 기록했다는 이유로 제재하지 않는다.
4. 입력과 출력을 모두 검사한다.
5. 사용자 원문은 기존 기록 외의 Moderation 로그에 중복 저장하지 않는다.
6. AI가 사용자의 상태·감정·위험도를 단정하지 않는다.
7. 자동 신고, 자동 연락, 자동 위치 추적을 하지 않는다.
8. Moderation 또는 AI 처리 실패 시에도 원문 기록은 보존한다.

## 3. 이용 연령

- Beta 1은 만 18세 이상만 이용할 수 있다.
- 온보딩에서 만 18세 이상 여부에 대한 필수 동의를 받는다.
- 만 18세 미만으로 확인되면 가입과 AI 기능 이용을 허용하지 않는다.
- 기존 만 14세 이상 동의 항목은 Beta 1 가입 기준으로 사용하지 않는다.
- 약관, 개인정보 처리방침, 온보딩 문구, 동의 데이터 구조를 만 18세 이상 기준으로 통일한다.

## 4. 전체 처리 흐름

```text
기록 저장
→ 입력 Moderation
→ 안전 처리 경로 결정
→ AI 응답 생성
→ 출력 Moderation
→ 통과 시 결과 저장·표시
→ 실패 시 안전 프롬프트로 1회 재생성
→ 재실패 시 정적 안전 안내 표시
```

### 4.1. 처리 순서

1. 기록 원문을 암호화하여 저장한다.
2. AI에 전달할 최소 범위의 문장을 구성한다.
3. 입력 Moderation을 실행한다.
4. 입력 결과에 따라 `NORMAL`, `RESTRICTED`, `CRISIS` 중 하나로 분기한다.
5. 분기별 프롬프트로 AI 응답을 생성한다.
6. 완성된 AI 응답에 출력 Moderation을 실행한다.
7. 안전한 응답만 사용자에게 표시한다.
8. 실패 상태와 최소 메타데이터를 저장한다.

### 4.2. 장애 처리

| 장애 지점 | 처리 |
|---|---|
| 기록 저장 실패 | AI 처리 미실행, 저장 실패 안내 |
| 입력 Moderation 실패 | AI 처리 중단, 기록 유지 |
| AI 생성 실패 | 시스템 재시도 정책 적용, 기록 유지 |
| 출력 Moderation 실패 | 응답 미표시, 기록 유지 |
| 안전 재생성 실패 | 정적 안전 안내 표시 |

## 5. Moderation 적용 기준

### 5.1. 기본 모델

- 입력·출력 Moderation 모델: `omni-moderation-latest`
- 초기 판단 기준: 카테고리별 boolean 결과
- `category_scores`는 초기 자동 차단 기준으로 사용하지 않는다.
- 모델명과 정책 버전은 설정값으로 관리한다.

### 5.2. 처리 등급

| 등급 | 기준 | 처리 |
|---|---|---|
| `NORMAL` | 일반 감정, 갈등, 욕설, 과거·제3자 위험 표현 | 일반 AI 회고 |
| `RESTRICTED` | 위협, 혐오 위협, 노골적 폭력, 불법 행위, 민감한 피해 경험 | 제한된 AI 회고 |
| `CRISIS` | 현재 자해 생각, 자해 의도·계획, 실행 중이거나 임박한 위험 | 일반 회고 중단, 안전 지원 |
| `BLOCKED_OUTPUT` | 생성된 AI 응답에 위험한 조언·방법·노골적 내용 포함 | 출력 미표시, 1회 안전 재생성 |

### 5.3. 일반 회고

다음 표현은 단순 언급만으로 차단하지 않는다.

- 우울함, 불안, 분노, 짜증
- 욕설과 관계 갈등
- 과거의 자해·폭력 경험
- 제3자의 자해·폭력 언급
- 폭력·혐오 표현을 들은 피해 경험
- 성적 경험 또는 피해 경험

일반 회고에서는 다음 원칙을 적용한다.

- 사용자의 감정과 경험을 평가하지 않는다.
- 감정을 단정하지 않고 후보 형태로 제시한다.
- 의료·법률·범죄 판단을 하지 않는다.
- 위험 표현을 불필요하게 반복하지 않는다.

### 5.4. 제한된 회고

다음 카테고리가 감지되면 제한된 회고 프롬프트를 사용한다.

- `harassment/threatening`
- `hate/threatening`
- `violence/graphic`
- `illicit`
- `illicit/violent`
- 기타 구체적인 위험 방법이나 실행 요청

제한된 회고 규칙:

- 위험한 방법, 절차, 수단을 제공하지 않는다.
- 노골적인 표현을 그대로 반복하거나 확대하지 않는다.
- 사건의 진위, 책임, 범죄 성립 여부를 단정하지 않는다.
- 사용자의 감정, 현재 필요, 안전한 다음 행동에 집중한다.
- 의료·법률·수사기관을 대체하는 판단을 제공하지 않는다.
- 필요 시 안전 지원 화면으로 이동할 수 있는 선택지를 제공한다.

### 5.5. 미성년자 성적 콘텐츠

- `sexual/minors`가 감지되면 일반 AI 회고 생성을 중단한다.
- 관련 내용을 요약·재구성·확장하지 않는다.
- 사용자 원문 기록은 그대로 보존한다.
- 안전한 정적 안내만 표시한다.
- 원문을 운영 로그나 신고 데이터에 자동 복제하지 않는다.

## 6. 자해·위기 단계 분류

`self-harm`, `self-harm/intent`, `self-harm/instructions` 관련 신호가 감지되면 별도 위기 분류를 실행한다.

| 단계 | 의미 | 처리 |
|---|---|---|
| `PAST_OR_CONTEXTUAL` | 과거 경험, 인용, 제3자 언급 | 일반 또는 제한 회고 |
| `EMOTIONAL_DISTRESS` | 절망감, 사라지고 싶은 감정 | 공감 표현, 현재 안전 상태 확인 선택지 |
| `CURRENT_IDEATION` | 현재 자해·죽음에 대한 생각 | 일반 회고 중단, 안전 지원 화면 우선 |
| `INTENT_OR_PLAN` | 의도, 계획, 방법, 시점 존재 | 즉시 도움 연결 안내 |
| `IMMEDIATE_DANGER` | 실행 중이거나 임박한 위험 | 가장 강한 안전 안내와 즉시 도움 요청 행동 제시 |

### 6.1. 위기 분류 원칙

- 진단값이 아니라 화면과 응답을 선택하는 라우팅 값으로만 사용한다.
- 위험도를 사용자에게 확정적으로 통보하지 않는다.
- 가족, 지인, 기관에 자동 연락하지 않는다.
- 위치 정보를 자동 수집하거나 추적하지 않는다.
- 신고 또는 구조 요청이 완료됐다고 표현하지 않는다.
- 사용자가 기록 화면으로 돌아갈 수 있게 한다.
- 위기 안내가 표시되어도 작성한 기록은 삭제하거나 수정하지 않는다.

### 6.2. 위기 안내 문구 원칙

- “당신은 위험합니다”처럼 단정하지 않는다.
- 안전이 걱정되는 표현이 감지됐다는 수준으로 알린다.
- 사용자가 잘못한 것처럼 표현하지 않는다.
- 기록을 다시 작성하도록 요구하지 않는다.
- AI가 사용자의 상황을 완전히 이해했다고 표현하지 않는다.
- 즉각적인 위험이 있는 경우에만 강한 행동 안내를 사용한다.
- 사용자가 직접 도움을 요청할 수 있는 행동 버튼을 제공한다.

## 7. 출력 안전 처리

1. AI 회고는 완성된 응답 단위로 검사한다.
2. 출력 Moderation을 통과하기 전에는 UI에 표시하지 않는다.
3. 위험 출력은 사용자에게 표시하지 않는다.
4. 안전 프롬프트로 최대 1회만 재생성한다.
5. 재생성 결과도 출력 Moderation을 통과해야 한다.
6. 재생성도 실패하면 기능별 정적 안내를 표시한다.
7. 안전 실패로 인한 시스템 재생성은 사용자의 재생성 횟수에 포함하지 않는다.
8. 위험 출력 원문은 일반 로그에 남기지 않는다.

## 8. 데이터 저장 정책

### 8.1. 저장 항목

- Moderation 모델명
- 정책 버전
- 입력·출력 구분
- 카테고리별 boolean 결과
- 필요한 범위의 카테고리 점수
- 최종 안전 처리 등급
- 위기 분류 단계
- 처리 경로
- 재생성 여부
- 오류 코드
- 실행 시각
- `ai_generation_run_id`

### 8.2. 저장 금지 항목

- Moderation 전용 로그에 복제한 사용자 원문
- 평문 상태의 AI 입력·출력
- 이메일, 전화번호, 실명 등 직접 식별자
- 위치 정보
- 불필요한 기기 식별 정보

### 8.3. 보관 기간

- 상세 카테고리 점수: 30일
- 30일 이후: 상세 점수 삭제 또는 비식별 집계로 전환
- 장기 통계: 카테고리별 건수와 처리 결과만 유지
- 신고 연결 데이터: 신고 보관 정책 기간 동안 별도 보관
- 사용자 원문: 기록 보관·삭제 정책에 따름

## 9. 사용자 식별값

OpenAI 요청의 `safety_identifier`에는 회원 ID를 직접 사용하지 않는다.

```text
safety_identifier = HMAC(memberId, serverSecret)
```

규칙:

- 동일 회원에 대해 안정적으로 같은 값이 생성되어야 한다.
- 역산할 수 없는 형태여야 한다.
- 이메일, 소셜 ID, 닉네임을 사용하지 않는다.
- HMAC 키는 애플리케이션 코드와 DB에 평문으로 저장하지 않는다.

## 10. 오탐 처리

- 안전 안내 화면에 `위기 상황이 아니에요` 선택지를 제공한다.
- 오탐 신고로 원문 기록을 변경하지 않는다.
- 해당 처리 결과를 `FALSE_POSITIVE_REPORTED`로 표시한다.
- 오탐 신고만으로 일반 AI 회고를 자동 재실행하지 않는다.
- 사용자가 요청한 경우에만 제한된 회고 경로로 다시 처리한다.
- 오탐 데이터는 임계값과 프롬프트 개선에 사용한다.

## 11. AI 응답 평가와 신고

### 11.1. 데이터 구분

| 구분 | 용도 |
|---|---|
| `ai_feedback` | 도움됨, 아쉬움, 도움 안 됨 |
| `ai_feedback_reports` | 부적절, 위험, 오류 응답 신고 |
| `member_ai_preferences` | 이후 응답에도 적용할 사용자 확정 선호 |

- 평가와 신고는 `ai_generation_run_id`에 연결한다.
- 신고 원문 전체를 기본 첨부하지 않는다.
- 사용자가 필요한 맥락과 기록 원문 제공 여부를 선택하게 한다.

### 11.2. 운영 처리 기한

| 신고 유형 | 확인 목표 |
|---|---|
| 일반 AI 응답 신고 | 72시간 이내 |
| 위험·자해 관련 신고 | 24시간 이내 |

### 11.3. 처리 기록

- 접수 시각
- 신고 유형
- 대상 생성 실행 ID
- 사용자 제공 맥락 범위
- 처리 상태
- 확인 시각
- 조치 유형
- 적용한 프롬프트·정책 버전
- 개선 반영 여부

## 12. 계정 및 기능 제한

- 감정, 경험, 위기 상황을 기록한 사용자는 제재하지 않는다.
- 범죄·폭력·자해 방법 요청은 해당 AI 응답만 거절한다.
- 반복적인 프롬프트 탈취, 자동화 호출, API 악용은 AI 기능을 일시 제한할 수 있다.
- 비정상 사용량은 Rate Limit으로 통제한다.
- 안전 카테고리 감지만으로 계정을 자동 영구 정지하지 않는다.
- 계정 제한은 Moderation 결과가 아니라 별도의 악용 정책과 사용 이력을 기준으로 판단한다.

## 14. 구현 규칙

### 14.1. 설정 관리

다음 항목을 코드에 하드코딩하지 않는다.

- Moderation 모델명
- 정책 버전
- 안전 프롬프트 버전
- 기능별 Rate Limit
- 상세 점수 보관 기간
- 시스템 재시도 횟수
- 신고 확인 목표 시간

### 14.2. 로그

- 원문 기록과 전체 AI 응답을 애플리케이션 로그에 남기지 않는다.
- 예외 메시지에 입력·출력 본문을 포함하지 않는다.
- 운영 로그에는 실행 ID, 상태, 오류 코드, 처리 시간만 남긴다.
- 추적에는 `ai_job_id`, `ai_generation_run_id`, 요청 상관관계 ID를 사용한다.

### 14.3. 재시도

- Moderation 장애 시 생성 모델을 호출하지 않는다.
- 일시적 외부 장애에만 시스템 재시도를 적용한다.
- 안전 실패는 동일 프롬프트로 반복 재시도하지 않는다.
- 출력 안전 재생성은 최대 1회로 제한한다.
- 시스템 재시도와 사용자 재생성을 별도 집계한다.

## 15. 출시 전 검증

### 15.1. 한국어 안전 테스트 세트

최소 200건 이상을 구성한다.

- 현재 위기 표현
- 자해 의도·계획·방법·시점 표현
- 과거 자해 경험
- 제3자의 위험 상황
- 비유적 표현
- 노래·영화·책 인용
- 욕설과 강한 분노
- 성적 경험과 피해 경험
- 폭력·범죄 피해 기록
- 위험 행동 요청
- 안전하지만 오탐 가능성이 높은 표현

### 15.2. 필수 검증 항목

- 기록이 항상 먼저 저장되는지
- Moderation 실패 시 AI 호출이 중단되는지
- 일반 감정 기록이 과도하게 차단되지 않는지
- 과거·제3자 언급이 현재 위기로 잘못 분류되지 않는지
- 현재 의도·계획 표현이 안전 경로로 전환되는지
- 위험 출력이 사용자에게 노출되지 않는지
- 재생성이 1회를 초과하지 않는지
- 정적 안내가 정상 표시되는지
- 원문이 로그에 남지 않는지
- 오탐 신고가 기록 원문을 변경하지 않는지
- 신고 데이터가 최소 범위로 저장되는지
- 만 18세 미만 가입이 차단되는지

### 15.3. 운영 지표

- 입력 Moderation 감지율
- 처리 등급별 건수
- 위기 단계별 건수
- 출력 차단율
- 안전 재생성 성공률
- 정적 안내 전환율
- 오탐 신고율
- 사용자 평가와 신고율
- 카테고리별 오탐·미탐 사례
